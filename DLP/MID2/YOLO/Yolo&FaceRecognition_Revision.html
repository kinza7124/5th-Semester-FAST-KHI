YOLO — Object Detection

You Only Look Once · Real-Time · Single Forward Pass

01Object Detection Basics
🧠 Four Core CV Tasks
  • ClassifyClassification — What is in the image? (label only, no location)
  • LocalizeLocalization — Where is a single object? (box + label)
  • DetectObject Detection — Multiple objects, each with location + class
  • SegmentSegmentation — Pixel-wise mask per object (most precise)
Two-Stage (R-CNN)

Region proposals first, then classify each. High accuracy, 5–20 FPS. Slower, complex.

One-Stage (YOLO)

Single pass end-to-end. 45+ FPS real-time. Lower complexity, great speed.

02Sliding Window Bottleneck
🔲 Three Critical Failures

Traditional detection scanned images sequentially, creating these problems:

  1. Multiple objects caught within a single scanning window — can't separate them
  2. Large objects spanning across multiple separate windows — fragmented detection
  3. Unbalanced bounding rectangles that fail to capture real-world object shapes
⚠️ Root Cause: The CNN runs independently for every window position, stride, and scale — massively redundant computation, no spatial sharing between overlapping regions.
03The YOLO Grid — Single-Shot Solution
🗺️ The S×S Grid

Instead of scanning, YOLO divides the entire image into an S×S grid simultaneously. The whole image is evaluated in one forward pass.

  • YOLOv1Uses a 7×7 grid
  • YOLOv3+Uses a 19×19 grid (finer resolution)
🏆 The Golden Rule: The single grid cell that contains the center of an object is exclusively responsible for detecting it. No other cell predicts that object.
04Anatomy of a Cell Prediction
📦 Per-Cell Output Variables
  • PcConfidence Score — Probability that an object actually exists in this cell (0 to 1)
  • bx, byCenter coordinates of the object — strictly bounded 0 to 1 relative to the cell
  • bw, bhWidth and Height of the bounding box — relative to the entire image, so it can span multiple cells
  • C1…CnClass probabilities — one per object class (e.g., car, pedestrian, dog)
Key distinction: bx, by are relative to the cell (0–1), but bw, bh are relative to the full image — this allows the bounding box to be larger than the responsible cell.
05Output Tensor Dimension
📐 YOLO Output Formula
Output Tensor = S × S × (B × 5 + C) S = Grid size (e.g., 7) B = Bounding boxes predicted per cell 5 = Core variables: [Pc, bx, by, bw, bh] C = Number of object classes

Example: 3×3 grid, B=2 boxes/cell, C=3 classes:

3 × 3 × (2×5 + 3) = 3 × 3 × 13

With anchor boxes, each object is assigned to a (Grid Cell, Anchor Box) pair:

3 × 3 × 2 anchor boxes × 8 params = 3 × 3 × 2 × 8
06Intersection Over Union (IoU)
📊 Measuring Prediction Accuracy

IoU measures the overlap between the predicted bounding box and the ground truth box.

IoU = |B_pred ∩ B_gt| / |B_pred ∪ B_gt| = Area of Intersection / Area of Union
  • 1.0Perfect Match — predicted box exactly equals ground truth
  • ≥ 0.5Correct Detection — standard threshold used in benchmarks
  • 0.0No Overlap — boxes don't touch at all

Final Confidence Score:

Score = P(class | object) × P(object) × IoU
07Non-Max Suppression (NMS)
🧹 Eliminating Duplicate Detections

Problem: When YOLO uses many grid cells, multiple nearby cells may all claim to detect the same object — producing many overlapping boxes for one object.

NMS Algorithm:

  1. Filter — Discard all boxes with confidence score below threshold (e.g., Pc < 0.6)
  2. Select — Pick the box with the highest confidence score
  3. Suppress — Remove all other boxes with IoU ≥ threshold vs the selected box
  4. Repeat — Continue until no overlapping duplicate boxes remain
Result: One clean, precise bounding box per detected object.
08Anchor Boxes
⚓ The Overlap Challenge

Limitation of standard YOLO: Each grid cell can only predict one object. If a pedestrian stands directly in front of a car, they share a center point — detection fails for one of them.

Solution — Anchor Boxes: Pre-assumed, common shapes provided to the network. Each grid cell can now predict multiple objects — one per anchor box.

Anchor 1: Human

Tall, narrow shape — matches pedestrian proportions

Anchor 2: Car

Wide, short shape — matches vehicle proportions

How anchors are designed: Hand-selected based on domain knowledge, or automatically derived using K-means clustering on the training dataset to find the most frequent object aspect ratios.
⚠️ Anchor Box Limitations
  • Limit 1A cell cannot detect more objects than it has anchor boxes
  • Limit 2Cannot detect two objects of the exact same anchor shape in one cell
  • Limit 3Requires careful selection of anchor sizes for the target domain
09Bounding Box Parameterization
🔧 Offset Predictions

The network doesn't output raw coordinates — it predicts offsets (tx, ty, tw, th) relative to an anchor box to refine the final box position and size:

bx = σ(tx) + cx ← sigmoid confines center to the cell by = σ(ty) + cy ← cx, cy = grid cell top-left corner bw = pw × e^(tw) ← pw, ph = anchor box dimensions bh = ph × e^(th) ← exponential allows any scale
  • cx, cyTop-left corner coordinates of the grid cell
  • pw, phWidth and height of the anchor box (prior)
  • σSigmoid function — constrains center offset between 0 and 1
  • e^tExponential — allows box to be any positive scale of anchor
10The YOLO Loss Function
📉 Three-Pillar Loss
Total Loss = λ₁·Lcoord + λ₂·Lconf + λ₃·Lclass
  • LcoordLocalization Loss — How accurately was the box drawn? Penalizes errors in center coordinates (x, y) and dimensions (w, h). Weight λ is higher (e.g., 5) since precise localization matters most.
  • LconfConfidence Loss — Is there actually an object here? Penalizes both false positives (claiming object exists) and false negatives (missing an object).
  • LclassClassification Loss — Did we identify the right class? Penalizes incorrect class predictions using cross-entropy.
Weighting factors (λ) balance the three components — localization errors are typically penalized more heavily than classification errors during training.
11Evaluating YOLO: mAP, Precision & Recall
Precision
TP / (TP + FP)

Of all objects YOLO claimed were cars — how many actually were?

Recall
TP / (TP + FN)

Of all actual cars in the image — how many did YOLO find?

📈 Mean Average Precision (mAP)

mAP is the primary benchmark metric for YOLO and object detection models. It is computed by:

  1. Computing the precision-recall curve for each object class at a given IoU threshold
  2. Computing the Average Precision (AP) = area under the P-R curve for each class
  3. Taking the mean of AP across all classes = mAP
A higher mAP means the model is both precise (few false positives) and high-recall (few missed detections) across all classes.
12YOLO Architecture
🏗️ YOLOv1 Network Structure
  • Layers24 Convolutional layers followed by 2 Fully Connected layers
  • InputPre-trained on ImageNet at 224×224, then fine-tuned at 448×448 for detection
  • EfficiencyAlternating 1×1 conv layers reduce feature space between 3×3 layers
  • LearningTransfer Learning — backbone weights from ImageNet classification task
🔄 Three-Part Architecture (Modern YOLO)
  • BackboneFeature Extraction — CNN capturing edges, textures (early), complex patterns (deep). Examples: Darknet-53, ResNet, CSPDarknet
  • NeckFeature Fusion — bridges backbone and head; aggregates multi-scale features via upsampling + downsampling (Feature Pyramid Network)
  • HeadDetection — produces final predictions: bounding boxes + class probabilities at multiple scales
🔄 Complete YOLO Pipeline
  1. Input Image — full image passed in (e.g., 448×448×3)
  2. Grid Division — image divided into S×S grid simultaneously
  3. ConvNet Processing — 24-layer network processes entire image in one pass
  4. NMS Filtering — Non-Max Suppression removes duplicate detections
  5. Final Bounding Boxes — clean detections with class labels and confidence
Key Philosophy: YOLO frames detection as a single regression problem — one CNN directly predicts boxes and classes. No region proposals, no multi-stage pipeline.

15One-Shot Learning Problem
1️⃣ Only One Photo Per Person

In most real systems (employee databases, ID verification, attendance), we only have one image per person. Standard deep learning needs thousands — so standard CNNs completely fail.

  1. Robustness decreases significantly as more persons are added to the database
  2. Entire network must be retrained every time a new person is added — not scalable
  3. With one training image, softmax-based CNN has insufficient data to learn discriminative features
Solution: Shift from classification to similarity learning — output the degree of difference between two faces instead of a class label.
16Siamese Networks
🔁 Parallel Twin Architecture

Two identical CNNs with shared weights processing two different images simultaneously. Each produces a 128-d encoding, then their distance is compared:

If d(f(x_i), f(x_j)) < τ → Verified Match (same person) If d(f(x_i), f(x_j)) ≥ τ → No Match (different persons)
Why shared weights? Both branches must use the same encoding function — so the same face always maps to the same region in embedding space regardless of which branch processes it. Enables one-shot inference without retraining.
📐 The Similarity Condition

Train network parameters so that the encoding function f(x) satisfies:

Same person: ||f(x_i) − f(x_j)||² → small Different person: ||f(x_i) − f(x_j)||² → large
17Facial Embeddings
🔢 128-Dimensional Face Vectors

The CNN compresses a face into a 128-byte numerical vector. The network's true job is compression:

  • Compact128 numbers fully represent a face
  • ComparableEuclidean distance between vectors measures similarity
  • RobustInvariant to pose, lighting, expression
Similar faces → similar 128-byte encodings. Different faces → highly distinct representations.
18Triplet Loss
🔺 The Three Images
A — Anchor

The baseline reference image of a person

P — Positive

Different photo, same person as anchor

N — Negative

Image of a completely different person

⚖️ Triplet Loss Equation
L(A,P,N) = max( ||f(A)−f(P)||² − ||f(A)−f(N)||² + α, 0 ) J = Σ L(Aᵢ, Pᵢ, Nᵢ) for i = 1 to m
  • Gap > 0Network is penalized — separation insufficient
  • Gap ≤ 0Loss = 0 — no penalty, already well separated
  • αMargin — enforces a significant, definitive gap to prevent lazy optimization
Without α: The network can trivially satisfy the constraint by mapping all faces to the same zero vector. The margin α forces a meaningful minimum separation.
⛏️ Hard Negative Mining

Random negatives are too easy → zero loss → no learning. We need Hard Negatives:

Select negatives where: d(A,P) ≈ d(A,N) — faces that look very similar but are different people

Keeping this initial difference low forces the network to detect very subtle, nuanced facial differences. Leads to faster convergence and better embeddings.

19FaceNet (Google, 2015)
🌐 Unified Embedding System
ComponentDetail
ArchitectureInception/ResNet CNN

BenchmarkState-of-the-art on LFW dataset
🔄 Complete Pipeline
  1. Face Detection — MTCNN locates and crops the face region
  2. Preprocessing — Resize, normalize, align using facial landmarks
  3. CNN Encoding — Inception/ResNet → 128-d L2-normalized embedding
  4. Distance Computation — Euclidean distance against database embeddings
  5. Threshold Decision — d < τ → match; d ≥ τ → unknown
Q&ATap to Reveal Answers
📗 YOLO Questions
Q1.What does "You Only Look Once" mean? How does it differ from R-CNN?▼
YOLO processes the entire image in a single forward pass through one CNN — it simultaneously predicts all bounding boxes and class probabilities across all grid cells at once. This is where "Look Once" comes from.

R-CNN (two-stage) first generates thousands of region proposals, then classifies each one separately. This creates massive overhead — 5–20 FPS. YOLO achieves 45+ FPS by treating detection as a single regression problem rather than a multi-stage pipeline.
Q2.Explain the YOLO Golden Rule and the output tensor formula.▼
Golden Rule: The single grid cell that contains the center of an object is exclusively responsible for detecting it. If a car's center falls in cell (3,4), only that cell predicts the car — even though the car physically spans multiple cells.

Output Tensor:
S × S × (B × 5 + C) S = grid size, B = boxes per cell, C = classes Example: 3×3 grid, B=2, C=3 → 3×3×13
With anchor boxes: S × S × B × (5 + C) where each anchor has its own [Pc, bx, by, bw, bh, C1...Cn].
Q3.What is IoU? Why is 0.5 used as a threshold?▼
IoU (Intersection over Union) measures the overlap between the predicted bounding box and the ground truth box:
IoU = Area of Intersection / Area of Union
A value of 1.0 = perfect alignment; 0.0 = no overlap.

Why 0.5? IoU ≥ 0.5 is the standard benchmark threshold from PASCAL VOC. At 0.5, the predicted box overlaps at least 50% of the union area — considered "good enough" to count as a correct detection. More strict benchmarks (like COCO) use IoU = 0.75 or average across thresholds 0.5:0.95.
Q4.Explain Non-Max Suppression step by step.▼
Problem: Multiple grid cells near an object may all predict it with high confidence, generating many overlapping boxes. NMS selects only the best one per object.

Algorithm:
  • Step 1: Discard all boxes with Pc < threshold (e.g., 0.6) — low confidence boxes gone
  • Step 2: Sort remaining boxes by confidence score (highest first)
  • Step 3: Take the top box — this is a kept detection
  • Step 4: Remove all other boxes with IoU ≥ 0.5 vs the kept box (they detect the same object)
  • Step 5: Repeat from Step 3 until no boxes remain
Run NMS separately per class to avoid suppressing detections of different object types.
Q5.What are anchor boxes and why are they needed?▼
Problem: Standard YOLO allows only one prediction per grid cell. If a pedestrian stands in front of a car (both centers in the same cell), one detection is lost.

Anchor boxes are pre-defined bounding box shapes with specific aspect ratios (e.g., tall narrow for people, wide short for cars). Each cell now predicts B boxes — one per anchor. Objects are assigned to the anchor with the highest IoU overlap with their shape.

Selection methods: Hand-picked based on domain knowledge, or automatically derived via K-means clustering on the training dataset's ground truth boxes to find the most common object proportions.
Q6.Explain the three components of the YOLO loss function.▼
Total Loss = λ₁·Lcoord + λ₂·Lconf + λ₃·Lclass
  • Lcoord (Localization Loss): MSE between predicted and ground truth [bx, by, bw, bh]. Weighted with higher λ (e.g., 5) because precise location matters most. Note: √w and √h are used to equalize contributions from large and small boxes.
  • Lconf (Confidence Loss): Penalizes both false positives (Pc predicted high but no object) and false negatives (object exists but Pc predicted low). Background cells use a lower weight λ_noobj (e.g., 0.5).
  • Lclass (Classification Loss): Cross-entropy or MSE on class probabilities C1…Cn for cells that contain an object.
Q7.Explain bounding box parameterization in YOLO. Why use sigmoid and exponential?▼
The network predicts offsets (tx, ty, tw, th) rather than absolute coordinates:
bx = σ(tx) + cx by = σ(ty) + cy bw = pw·e^(tw) bh = ph·e^(th)
Why sigmoid for center? The center must stay within the responsible grid cell (between 0 and 1 relative to cell). Sigmoid naturally constrains output to [0, 1], preventing the box from jumping to another cell.

Why exponential for size? Box dimensions must be positive and can be any scale relative to the anchor. The exponential function ensures positivity (e^t > 0 always) and allows smooth scaling — negative t shrinks the box, positive t grows it.
📘 Face Recognition Questions
Q8.Why do standard classification CNNs fail at face recognition?▼
Standard CNNs with softmax output fail because:
  • One-shot problem: Traditional deep learning needs thousands of examples per class. Most real-world systems have only 1 photo per person.
  • Scalability: Every time a new person joins, the entire network must be retrained from scratch with a new output neuron.
  • Robustness degrades: As more people are added to the database, accuracy drops — the softmax output space becomes too crowded.
The fix is to learn a similarity function (Siamese Network) instead of a classification function.
Q9.Write the Triplet Loss formula and explain every term.▼
L(A,P,N) = max( ||f(A)−f(P)||² − ||f(A)−f(N)||² + α, 0 )
  • f(A) — 128-d embedding of the Anchor image (reference)
  • f(P) — 128-d embedding of the Positive (same person, different photo)
  • f(N) — 128-d embedding of the Negative (different person)
  • ||f(A)−f(P)||² — squared Euclidean distance between anchor and positive (want small)
  • ||f(A)−f(N)||² — squared Euclidean distance between anchor and negative (want large)
  • α — margin hyperparameter enforcing a minimum separation gap
Loss is 0 when anchor-positive distance is already much smaller than anchor-negative (by at least α). Otherwise the network is penalized and must adjust weights.
Q10.What is Hard Negative Mining and why is it critical for training?▼
Hard Negative Mining selects training triplets where the negative example is very similar to the anchor — specifically where d(A,P) ≈ d(A,N) (faces from different people that look almost alike).

Why critical:
  • Random negatives are already far apart → zero loss → no gradient, no learning
  • Hard negatives produce non-zero loss → meaningful gradient → real learning
  • Forces the network to detect extremely subtle facial differences (glasses vs no glasses, similar haircuts)
  • Leads to faster convergence and significantly better embedding quality
