Transformer Variants

A complete reference covering Encoder-Only, Decoder-Only, and Encoder–Decoder architectures — how they work, when to use them, and what they power.

Encoder-Only Decoder-Only Encoder–Decoder
Foundation
What is a Transformer?

Transformers are neural network architectures built on the self-attention mechanism. Unlike RNNs that process tokens sequentially, transformers process the entire sequence in parallel, attending to all positions simultaneously. Three structural variants arise from how the encoder and decoder blocks are combined.

💡 The key innovation: Attention allows each token to directly "look at" any other token in the sequence, weighted by relevance. This removes the bottleneck of fixed-size hidden states in RNNs and enables capturing long-range dependencies.

Variant 01
Encoder-Only Transformer
01

Encoder-Only

Reads the full input bidirectionally · Produces rich contextual embeddings · Understands, doesn't generate

Architecture

  • Structure: Stack of N encoder layers only
  • Attention: Bidirectional — each token can attend to ALL other tokens (left and right)
  • Output: Contextualized embeddings for every token
  • Training: Masked Language Modeling (MLM) — randomly mask 15% of tokens, predict them
  • No autoregressive: Not designed for text generation

Applications

  • Text Classification — sentiment, topic
  • Named Entity Recognition (NER)
  • Question Answering (extractive)
  • Semantic Similarity / embedding search
  • Coreference Resolution
  • Token Classification tasks

How it works

  • Entire input sequence fed simultaneously (no left-to-right constraint)
  • Each encoder layer applies bidirectional multi-head self-attention
  • Produces one embedding vector per input token, enriched with full-context information
  • Final [CLS] token embedding used for classification tasks; per-token embeddings used for span tasks

Real-World Models

BERT RoBERTa DistilBERT ALBERT ELECTRA DeBERTa
Figure 2 — Encoder-Only architecture: bidirectional self-attention allows full context access.
🔑 Key Insight: Because every token can see every other token during training AND inference, the encoder builds extremely rich semantic representations. BERT's breakthrough was showing these representations could be fine-tuned with minimal task-specific layers to achieve state-of-the-art on 11 NLP benchmarks simultaneously.
Variant 02
Decoder-Only Transformer
02

Decoder-Only

Generates text one token at a time · Causal (masked) attention · Powers all major LLMs (GPT, LLaMA, Claude)

Architecture

  • Structure: Stack of N decoder layers only
  • Attention: Causal (masked) — each token attends only to itself and past tokens
  • Output: One token at a time (autoregressive)
  • Training: Next-token prediction on shifted sequence
  • Input: Entire prompt + history fed as single sequence

Applications

  • Chatbots & Conversational AI
  • Code Generation (Copilot, Codex)
  • Story / Creative Writing
  • Reasoning & Chain-of-Thought
  • Summarization (generative)
  • Instruction Following

How it works

  • Prompt is tokenized and embedded with positional encodings
  • Each layer applies masked multi-head self-attention (future tokens masked out)
  • Final hidden state → linear projection → softmax → probability distribution over vocabulary
  • Sample/argmax the next token; append to sequence; repeat until end token or max length

Variant 03
Encoder–Decoder Transformer
03

Encoder–Decoder

Bidirectional encoding + autoregressive decoding · Two separate stacks · Seq2Seq tasks where input ≠ output

Architecture

  • Encoder Stack: Bidirectional self-attention on source
  • Decoder Stack: (1) Masked self-attention within decoder, (2) Cross-attention to encoder outputs
  • Cross-Attention: Decoder queries from encoder's key/value projections
  • Training: Next-token prediction on target sequence (shifted right)
  • Input → Output: Different sequences (translation, summarization)

Applications

  • Machine Translation (en → fr, etc.)
  • Text Summarization (abstractive)
  • Image Captioning
  • Question Generation
  • Document Generation
  • Speech Recognition (Whisper)

How it works

  • Encoder processes entire source sequence with bidirectional attention → hidden representations
  • Decoder generates output tokens one at a time (autoregressive)
  • At each decoder step: masked self-attention over decoded tokens so far, then cross-attention over encoder outputs
  • Cross-attention: decoder's Q attends to encoder's K, V — enabling the decoder to "consult" the source at each generation step

Decoder-Only Decoder stack Causal (masked) self-attention Input → Autoregressive output Generation, scalability for LLMs Chatbots, code generation, creative writing

Decision Guide
Use Encoder-Only when…
  • → You need to understand text
  • → Task = classification or span detection
  • → You want dense semantic embeddings
  • → Fast inference over many documents
Use Decoder-Only when…
  • → You need to generate open-ended text
  • → Building a chatbot / assistant
  • → Scaling to billions of parameters
  • → In-context learning / few-shot prompting
Use Encoder–Decoder when…
  • → Input and output are different sequences
  • → Translation or summarization tasks
  • → You need full source context at each decode step
  • → Structured output from unstructured input

Chatbot Using Decoder-Only Transformer

End-to-end walkthrough of how a GPT / LLaMA-style chatbot turns user input into an intelligent response.

Step 01 · User Interaction

User sends a message

User types a query. The system packages it with conversation history and a system prompt into a single text string.

Step 02 · Conversation Context

Full history maintained

The entire conversation (system + past turns + current message) is kept as context. No separate memory — it's all in the prompt.

Step 03 · Prompt Formation

Special tokens applied

Format: <s>[SYSTEM]…[USER]…[ASSISTANT] — role tags tell the model who is speaking.

Step 04 · Tokenization

Text → Token IDs

BPE/SentencePiece splits text into sub-word units. "Give an example" → [345, 621, 2367, 13]. Each ID maps to an embedding vector.

Step 05 · Positional Encoding

Position added to embeddings

Since transformers have no inherent order, sinusoidal or learned positional encodings are added to each token embedding before the first layer.

Step 06 · Decoder Layers (Nx)

Masked multi-head self-attention

N identical layers: each applies causal attention + feed-forward network. The final hidden state represents "what comes next" in context.

Step 07 · Generation Loop (Inference)

Exam Prep
Interview Q & A

Tap any question to reveal the answer. Covers foundational, architectural, and comparative questions.

01 · Fundamentals
Q1 What is self-attention and how does it differ from traditional attention? ▼
Self-attention (intra-attention) computes attention within a single sequence — every token attends to every other token in the same sequence. Traditional (cross) attention attends between two different sequences (e.g., encoder output and decoder state in seq2seq RNNs). Self-attention is computed as: Attention(Q,K,V) = softmax(QKᵀ / √dₖ) · V where Q, K, V are linear projections of the same input sequence.
Q2 Why is positional encoding necessary in transformers? ▼
Transformers process all tokens in parallel with no inherent notion of order — unlike RNNs which process sequentially. Without positional encoding, "the cat sat" and "sat the cat" would produce identical representations. Positional encodings (sinusoidal or learned) are added to token embeddings to inject position information. Sinusoidal PE uses sin/cos at different frequencies, allowing the model to generalize to sequence lengths longer than seen in training.
Q3 What is multi-head attention and why use multiple heads? ▼
Multi-head attention runs h parallel attention heads, each with its own Q, K, V projection matrices (dimension dₖ = d_model / h). The outputs are concatenated and linearly projected. Using multiple heads allows the model to simultaneously attend to different aspects of the sequence — one head might capture syntactic relationships, another semantic ones, another co-reference. It gives the model richer representational capacity than a single large attention operation.
Q4 What is the role of the Feed-Forward Network (FFN) in each transformer layer? ▼
The FFN is applied independently to each token position after the attention sub-layer. It consists of two linear transformations with a non-linearity: FFN(x) = max(0, xW₁ + b₁)W₂ + b₂. The inner dimension is typically 4× the model dimension (e.g., 3072 for d_model=768). While attention captures token interactions, the FFN acts as a per-token "memory" that stores and retrieves factual associations. Recent research suggests much factual knowledge is stored in FFN weights.
Q5 What is residual connection and layer normalization, and why are they used? ▼
Residual connections add the input of a sub-layer to its output: output = x + Sublayer(x). This enables gradient flow through deep networks (avoiding vanishing gradients) and lets layers learn residual refinements rather than full transformations. Layer Normalization normalizes activations across the feature dimension (not batch dimension), stabilizing training. Together they enable training transformers with 100+ layers. Pre-norm (LayerNorm before sublayer) is used in modern LLMs for more stable training.
02 · Encoder-Only (BERT-family)
Q6 How does BERT's Masked Language Modeling (MLM) training objective work? ▼
In MLM, 15% of input tokens are randomly selected. Of these: 80% are replaced with [MASK], 10% with a random token, and 10% kept unchanged. The model must predict the original token at masked positions. This forces bidirectional context learning — the model must use both left and right context to fill in masked tokens. The 10/10 strategy prevents the model from "knowing" when it needs to predict, making all representations useful.
Q7 Why can't BERT generate text directly? ▼
BERT uses bidirectional attention — each token sees all other tokens including future ones. For autoregressive generation, the model must predict the next token conditioned only on past tokens. If BERT tried to generate token at position t, it would "cheat" by seeing future tokens t+1, t+2… during training, making generation meaningless. Autoregressive generation requires causal (masked) attention — which is what decoder-only models use. BERT is fundamentally an understanding model, not a generation model.
Q8 What is the [CLS] token in BERT and how is it used? ▼
[CLS] (classification token) is prepended to every input sequence. Because of bidirectional attention, by the final layer its representation has "attended to" the entire sequence and aggregates global information. For classification tasks (sentiment, NLI), the [CLS] embedding is fed into a classification head (linear layer + softmax). For tasks like NER or QA, per-token embeddings are used instead. The [SEP] token separates paired sequences (e.g., sentence A and B in NSP).
03 · Decoder-Only (GPT-family)
Q9 What is the causal (autoregressive) language modeling objective? ▼
Causal LM trains the model to maximize the probability of each token given all preceding tokens: L = Σ log P(xₜ | x₁, x₂, ..., xₜ₋₁). During training, the target is the input shifted right by one position — at each step t, the model predicts token t given tokens 1…t-1. Crucially, a causal mask ensures no future tokens are attended to, making training and inference consistent. This simple objective, applied at scale, produces powerful general-purpose language models.
Q10 What is temperature in text generation and how does it affect output? ▼
Temperature T scales logits before softmax: P(xᵢ) = exp(logit_i / T) / Σ exp(logit_j / T). With T < 1 (e.g., 0.7): distribution sharpens, high-probability tokens become even more likely — output is focused, deterministic, less creative. With T > 1 (e.g., 1.5): distribution flattens, low-probability tokens get more chance — output is more varied and creative but potentially less coherent. T=1 is the raw model distribution. T→0 approaches greedy decoding.
Q11 What is KV-cache and why is it important for efficient inference? ▼
During autoregressive generation, each new token requires attention over all previous tokens. Without caching, all K and V projections would be recomputed for every past token at each step — O(n²) computation. KV-cache stores the computed Key and Value tensors from previous steps, so at step t only the new token's K, V are computed and appended to the cache. This reduces generation time from O(n²) to O(n) for the cached portion. KV-cache is the primary reason inference is feasible for long sequences, but it consumes significant GPU memory (the "KV-cache memory" bottleneck).
Q12 What is instruction tuning / RLHF and why is it needed after pretraining? ▼
A pretrained decoder-only model is a "next-token predictor" — it will complete any text in a plausible way, but doesn't know how to follow instructions or be helpful/safe. Instruction tuning (SFT) fine-tunes on (instruction, response) pairs, teaching the model to answer questions and follow directives. RLHF (Reinforcement Learning from Human Feedback) then uses a reward model trained on human preference comparisons to further align the model via PPO or similar algorithms. Together they transform a raw LM into a usable assistant (ChatGPT, Claude, etc.).
04 · Encoder–Decoder
Q13 Explain cross-attention in the encoder–decoder architecture. ▼
In each decoder layer, after masked self-attention, there is a cross-attention sub-layer. The Query (Q) vectors come from the previous decoder layer, while the Key (K) and Value (V) vectors come from the encoder's final output. This allows each decoder step to "look at" all encoder representations and decide which source tokens are most relevant for generating the next target token. For machine translation, when generating "cloud," cross-attention might attend strongly to the source word "nuage."
Q14 How does T5's "text-to-text" framework unify NLP tasks? ▼
T5 (Text-to-Text Transfer Transformer) reformulates every NLP task as mapping an input text string to an output text string. Classification becomes: input "sst2 sentence: The movie was great" → output "positive". Translation: input "translate English to French: Hello" → output "Bonjour". Summarization: input "summarize: ..." → output summary. This unification means one model architecture and one training procedure handles everything — only the prefix text indicates the task. It makes multi-task training trivially easy.
05 · Comparative & Advanced
Q15 Why have modern LLMs moved to decoder-only instead of encoder–decoder? ▼
Several reasons: (1) Simplicity — decoder-only uses one stack, half the parameters for the same capacity. (2) In-context learning — autoregressive models can use prompts to condition behavior without fine-tuning. (3) Scaling — the causal LM objective is extremely data-efficient; any raw text is valid training data. (4) Emergent capabilities — at sufficient scale, decoder-only models develop classification, reasoning, and translation capabilities without explicit architectural support. Encoder–decoder excels at fixed seq2seq tasks, but decoder-only is more general-purpose.
Q16 What is the difference between top-k and top-p (nucleus) sampling? ▼
Top-k keeps the k highest-probability tokens and samples from them (k is fixed, e.g., 50). Problem: when the distribution is sharp, k may still include low-probability noise; when flat, k may exclude reasonable options. Top-p (nucleus) dynamically keeps the smallest set of tokens whose cumulative probability ≥ p (e.g., 0.9). If the model is confident, the nucleus is small (maybe just 2-3 tokens); if uncertain, the nucleus is large (many tokens). Top-p adapts to the distribution shape at each step, generally producing higher-quality text.
Q17 What is the attention complexity problem and how does Flash Attention address it? ▼
Standard attention has O(n²) time and memory complexity with sequence length n — for n=10,000 the attention matrix alone requires 100M entries. Flash Attention (Dao et al., 2022) reformulates attention to be IO-aware: it tiles the QK computation to stay in SRAM rather than reading/writing the full attention matrix to HBM (slow GPU memory). Result: same mathematical output, but O(n) memory and significantly faster wall-clock time. Flash Attention v2/v3 further optimizes for multi-head and GQA setups, enabling 100k+ context windows in models like Claude.
Q18 What is tokenization and why do all transformers use sub-word tokenization? ▼
Tokenization converts raw text into integer IDs. Word-level tokenization has huge vocabularies and can't handle OOV words. Character-level creates very long sequences. Sub-word methods (BPE, WordPiece, SentencePiece) find a middle ground: common words are single tokens ("the" → 1), rare words split into sub-words ("unbelievable" → ["un", "believ", "able"]). This limits vocabulary to ~30k-100k tokens while handling any text, balancing sequence length vs. vocabulary coverage. BPE (Byte-Pair Encoding) is most common — it iteratively merges the most frequent adjacent pairs.
Q19 What is Grouped Query Attention (GQA) and why is it used in LLaMA 2/3? ▼
Standard Multi-Head Attention (MHA) has h query heads, h key heads, and h value heads. Multi-Query Attention (MQA) uses one shared K, V pair for all query heads — reduces KV-cache memory by h× but reduces quality. Grouped Query Attention (GQA) is a middle ground: G groups of query heads share one K, V pair each (G between 1 and h). LLaMA 2 70B uses G=8. Benefits: KV-cache is h/G× smaller → longer context, faster inference; quality close to MHA. It's the standard design in modern production LLMs.
Q20 Compare BERT vs GPT for a sentiment classification task. Which would you use and why? ▼
For sentiment classification, BERT (encoder-only) is the better choice. Reasons: (1) BERT's bidirectional attention captures full context — important for negation ("not bad" vs "bad"). (2) Sentence-level classification uses the [CLS] embedding naturally. (3) BERT can be fine-tuned with minimal task-specific parameters (just a linear head). (4) Much smaller and faster than comparable GPT models. GPT could be used via prompting ("Is this review positive or negative: ...") but requires much larger models to match fine-tuned BERT performance, and is slower at inference time.
