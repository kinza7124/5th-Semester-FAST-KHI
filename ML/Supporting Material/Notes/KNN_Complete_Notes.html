01

What is KNN?

K-Nearest Neighbors (KNN) is one of the simplest and most intuitive machine learning algorithms. The core idea is beautifully simple:

"Tell me who your neighbors are, and I'll tell you who you are."

KNN is a supervised learning algorithm. It can be used for both classification (predicting a category) and regression (predicting a number).

🦆 The Duck Analogy

If something walks like a duck, swims like a duck, and quacks like a duck — it's probably a duck. KNN classifies new data points based on what their closest known neighbors are labeled as.

Real-Life Example

Imagine you move to a new city and want to know if a neighborhood is "safe." You look at the 5 nearest neighborhoods. If 4 out of 5 are labeled "safe," you conclude your neighborhood is probably safe too. That's KNN — majority vote among K nearest neighbors.

📌 Key Properties
  • Non-parametric — makes no assumptions about data distribution
  • Instance-based — stores all training data
  • Lazy learner — no training phase (explained next)
  • Works for both classification and regression
02

Why is KNN a "Lazy Learner"?

🤔 Eager Learner (e.g. Decision Tree)

  • Learns a model during training
  • Training is slow
  • Prediction is fast
  • Model is stored, not raw data

😴 Lazy Learner (KNN)

  • No model built during training
  • Training is instant
  • Prediction is slow
  • All raw training data is stored
💡 Why "Lazy"?

KNN is called lazy because it does zero work during the training phase. It simply stores every training example. All the computation is deferred to prediction time — only when a new test point arrives does KNN compute distances to every stored training point.

This has consequences:

  • Fast training: Just store the data — O(1) time
  • Slow prediction: Must compare against all N training points — O(N·d) time where d = dimensions
  • High memory: Must keep all training data in memory
⚠️ Interview Trap

When asked "What is the training time complexity of KNN?" — answer is O(1) (trivial, just store data). Test time is O(N·d) per query. This is the opposite of most algorithms!

03

KNN Working Steps

1

Choose K

Decide how many neighbors to consider. K=1 means only the single closest point. K=5 means consider 5 closest and take majority vote.

2

Compute Distance / Similarity

For every training point, calculate how "close" it is to the test point. Common metrics: Euclidean, Manhattan, Cosine Similarity.

3

Sort and Select K Nearest

Rank all training points by distance (closest first). Pick the top K.

4

Majority Vote (Classification)

Count which class appears most among the K neighbors. Assign that class to the test point.

5

Average (Regression)

For regression, take the average of the K neighbors' values instead of majority vote.

04

Euclidean Distance

This is the straight-line ("as the crow flies") distance between two points. Think of using a ruler to measure the shortest path between two points on paper.

Formula d(A,B) = √[ Σ (Aᵢ − Bᵢ)² ]

For 2D points (x₁,y₁) and (x₂,y₂) this simplifies to the familiar Pythagorean theorem:

d = √[ (x₂−x₁)² + (y₂−y₁)² ]

Solved Example 1 — 2D Points

Given

Point A = (1, 5), Point B = (4, 1)

Find the Euclidean distance.

Step 1: Identify coordinates A = (1, 5) → x₁=1, y₁=5 B = (4, 1) → x₂=4, y₂=1 Step 2: Apply formula d(A,B) = √[ (4−1)² + (1−5)² ] = √[ (3)² + (−4)² ] = √[ 9 + 16 ] = √25 = 5

Solved Example 2 — From Lecture (Manhattan Distance Context)

Given — KNN Training Data

Training: F1=1, F2=5, Class=0  |  F1=0, F2=8, Class=0

F1=0, F2=6, Class=1  |  F1=1, F2=2, Class=1

Test Sample 1: F1=1, F2=3

Using Manhattan distance (as in the lecture — we'll cover that next), but let's also compute Euclidean:

Euclidean Distance from Test(1,3) to each training point: → To (1,5): Class 0 d = √[(1−1)² + (3−5)²] = √[0 + 4] = √4 = 2.0 → To (0,8): Class 0 d = √[(1−0)² + (3−8)²] = √[1 + 25] = √26 ≈ 5.1 → To (0,6): Class 1 d = √[(1−0)² + (3−6)²] = √[1 + 9] = √10 ≈ 3.16 → To (1,2): Class 1 d = √[(1−1)² + (3−2)²] = √[0 + 1] = √1 = 1.0 K=1: nearest is (1,2) with d=1.0 → Class 1 Prediction: Class 1

Solved Example 3 — 3D Vectors

Given

A = (1, 2, 3), B = (4, 0, 1)

d(A,B) = √[(4−1)² + (0−2)² + (1−3)²] = √[(3)² + (−2)² + (−2)²] = √[9 + 4 + 4] = √17 ≈ 4.12
⚠️ Problem with Euclidean Distance for Text

Euclidean distance is sensitive to document length. If Doc A = (1,1) and Doc B = (10,10), they represent the same word proportions but Euclidean distance = √162 ≈ 12.7. A longer document looks "far" even when content is identical. This is why cosine similarity is preferred for text!

05

Manhattan Distance

Also called City Block Distance or Taxicab Distance. Instead of measuring straight-line distance, it measures distance if you can only move horizontally or vertically — like navigating city blocks in a grid (like Manhattan, New York).

Formula d(A,B) = Σ |Aᵢ − Bᵢ|

No squaring, no square root — just the sum of absolute differences.

Solved Example 1 — From Lecture

Given

Test Sample 1: (F1=1, F2=3)

Training Sample 1: (F1=1, F2=5), Class=0

d = |1−1| + |3−5| = |0| + |−2| = 0 + 2 = 2

All 4 Distances — Full Lecture Example

Test Point: (1, 3) — find K=1 nearest neighbor
Training Point Class Calculation Distance
(1, 5) 0 |1−1| + |3−5| = 0 + 2 2
(0, 8) 0 |1−0| + |3−8| = 1 + 5 6
(0, 6) 1 |1−0| + |3−6| = 1 + 3 4
(1, 2) 1 |1−1| + |3−2| = 0 + 1 1 ← Nearest
✅ K=1 Result

Nearest neighbor is (1,2) with distance=1 and Class=1. So Test Sample 1 is classified as Class 1.

Solved Example 2 — 3D

Given

A = (3, 6, 2), B = (1, 4, 5)

d = |3−1| + |6−4| + |2−5| = |2| + |2| + |−3| = 2 + 2 + 3 = 7

✅ Manhattan Advantages

  • More robust to outliers
  • No squaring so large differences don't dominate
  • Better for high-dimensional data
  • Computationally cheaper (no sqrt)

❌ Manhattan Disadvantages

  • Less geometrically natural
  • Doesn't represent actual shortest path
  • Can mislead when data is continuous
06

Minkowski Distance

Minkowski is the generalized form that includes both Euclidean and Manhattan as special cases.

General Formula d(A,B) = ( Σ |Aᵢ − Bᵢ|ᵖ )^(1/p)
p valueNameNotes
p = 1Manhattan DistanceSum of absolute differences
p = 2Euclidean DistanceStraight-line distance
p → ∞Chebyshev DistanceMaximum of absolute differences

Solved Example

Given

A = (1, 2), B = (4, 6). Calculate for p=1, p=2, p=3

p=1 (Manhattan): d = |1−4| + |2−6| = 3 + 4 = 7 p=2 (Euclidean): d = (|1−4|² + |2−6|²)^(1/2) = (9+16)^0.5 = √25 = 5 p=3: d = (|3|³ + |4|³)^(1/3) = (27+64)^(1/3) = (91)^(1/3) ≈ 4.50
💡 Key Insight

As p increases, the distance becomes more dominated by the largest single dimension difference. For p→∞ (Chebyshev), distance = max(|3|, |4|) = 4.

07

Cosine Similarity

Instead of measuring how far apart two vectors are, cosine similarity measures the angle between them. If two vectors point in the same direction, they are similar — regardless of how long they are.

Formula cos(A,B) = (A · B) / (||A|| × ||B||)
= Σ(AᵢBᵢ) / [ √(ΣAᵢ²) × √(ΣBᵢ²) ]
📐 Geometric Intuition

Cosine similarity = cos(θ) where θ is the angle between the two vectors.
cos(0°) = 1.0 → vectors are identical (perfectly similar)
cos(90°) = 0.0 → vectors are perpendicular (completely unrelated)
cos(180°) = -1.0 → vectors point in opposite directions

Solved Example 1 — Basic (from KNN.pdf)

Given

A = (1, 2, 3), B = (2, 1, 2)

Find cosine similarity.

1

Dot Product A · B

A · B = (1×2) + (2×1) + (3×2) = 2 + 2 + 6 = 10
2

Magnitude of A (||A||)

||A|| = √(1² + 2² + 3²) = √(1 + 4 + 9) = √14 ≈ 3.742
3

Magnitude of B (||B||)

||B|| = √(2² + 1² + 2²) = √(4 + 1 + 4) = √9 = 3
4

Cosine Similarity

cos(A,B) = 10 / (√14 × 3) = 10 / (3.742 × 3) = 10 / 11.22 ≈ 0.89
✅ Interpretation

Cosine similarity of 0.89 means the vectors are highly similar (angle ≈ 27°). They point in nearly the same direction.

Solved Example 2 — Text Document Vectors

Vocabulary = {cat, dog}

Doc1: "cat cat dog" → (2, 1)
Doc2: "cat dog" → (1, 1)
Doc3: "dog dog dog dog" → (0, 4)

Similarity(Doc1, Doc2)

Step 1: Dot Product (2×1) + (1×1) = 2 + 1 = 3 Step 2: ||Doc1|| = √(2²+1²) = √(4+1) = √5 ≈ 2.236 Step 3: ||Doc2|| = √(1²+1²) = √2 ≈ 1.414 Step 4: Cosine Similarity cos = 3 / (√5 × √2) = 3 / √10 = 3 / 3.162 ≈ 0.95 ← Very similar!

Similarity(Doc1, Doc3)

Step 1: Dot Product (2×0) + (1×4) = 0 + 4 = 4 Step 2: ||Doc1|| = √5 ≈ 2.236 Step 3: ||Doc3|| = √(0²+4²) = √16 = 4 Step 4: Cosine Similarity cos = 4 / (√5 × 4) = 4 / (2.236 × 4) = 4 / 8.944 ≈ 0.45 ← Less similar

Length Invariance Demo — Doc2 vs Doc2_long

Doc2 = (1,1), Doc2_long = (10,10) ← Same proportions, longer Dot Product = (1×10) + (1×10) = 20 ||Doc2|| = √(1+1) = √2 ≈ 1.414 ||Doc2_long|| = √(100+100) = √200 ≈ 14.14 cos = 20 / (1.414 × 14.14) = 20 / 20.0 = 1.0 ← Perfect similarity! Length doesn't matter

Solved Example 3 — KNN Classification with Cosine

Training Data

P1=(1,0,1) Class A  |  P2=(0,1,1) Class B  |  P3=(1,1,0) Class A

Test T = (1,1,1), K=3

||T|| = √(1+1+1) = √3 ≈ 1.732 ||P1|| = ||P2|| = ||P3|| = √2 ≈ 1.414 cos(T, P1): T·P1 = (1×1)+(1×0)+(1×1) = 2 cos = 2/(√3×√2) = 2/2.449 ≈ 0.816 → Class A cos(T, P2): T·P2 = (1×0)+(1×1)+(1×1) = 2 cos = 2/(√3×√2) ≈ 0.816 → Class B cos(T, P3): T·P3 = (1×1)+(1×1)+(1×0) = 2 cos = 2/(√3×√2) ≈ 0.816 → Class A K=3 neighbors: {A, B, A} Majority Vote → Class A ✅

Euclidean vs Cosine — Why Use Cosine?

🚨 The Core Problem with Euclidean for Text

Euclidean distance treats longer documents as farther away even if they contain the same words in the same proportions. A short article and its 5-page expanded version would appear "distant" under Euclidean distance.

Side-by-Side Comparison

Setup

Doc1="cat cat dog" → (2,1)  |  Doc2="cat dog" → (1,1)  |  Doc3="dog dog dog dog" → (0,4)

Euclidean Results

d(Doc1, Doc2) = √[(2−1)² + (1−1)²] = √[1+0] = 1.0 d(Doc1, Doc3) = √[(2−0)² + (1−4)²] = √[4+9] = √13 ≈ 3.6 Now: Doc2_long = (10,10) — same as Doc2 but longer document d(Doc2, Doc2_long) = √[(1−10)² + (1−10)²] = √[81+81] = √162 ≈ 12.7 ❌ Same content, looks very far apart!

Cosine Results

cos(Doc1, Doc2) ≈ 0.95 ✅ Very similar (correct!) cos(Doc1, Doc3) ≈ 0.45 ✅ Less similar (correct!) cos(Doc2, Doc2_long) = 1.0 ✅ Identical content = perfect similarity!

MeasuresStraight-line distanceAngle between vectors
Affected by length?YES — longer = fartherNO — length-independent
Range0 to ∞−1 to +1 (usually 0 to 1)

✅ Rule of Thumb
  • Use Euclidean when magnitude matters (e.g., house prices, physical measurements)
  • Use Cosine when direction matters (e.g., text documents, user preferences, word embeddings)
  • Use Manhattan when robustness to outliers matters

How to Select the Value of K

K too small (e.g. K=1)

  • Very sensitive to noise/outliers
  • Decision boundary is jagged
  • High variance, low bias
  • May overfit

K too large (e.g. K=N)

  • Includes points from other classes
  • Decision boundary is over-smoothed
  • Low variance, high bias
  • May underfit

Methods to Choose K

1

Square Root Rule (Quick Heuristic)

K ≈ √N where N = number of training samples. For N=100, K≈10. Simple but not always optimal.

2

Cross-Validation (Best Practice)

Try K = 1, 3, 5, 7, ... and measure validation error for each. Pick K with lowest error. This is what the lecture example demonstrates.

3

Use Odd K for Binary Classification

Using odd K (1, 3, 5, 7...) avoids tie-breaking problems when you have 2 classes.

Normalization / Feature Scaling

⚠️ The Scaling Problem

Without normalization, features with larger ranges dominate the distance calculation. Example: height (1.5m–1.8m) vs income ($10K–$1M). A tiny income difference will completely overpower height differences in Euclidean distance!

Min-Max Normalization (Scale to [0,1])

x_norm = (x − x_min) / (x_max − x_min)

Solved Example — Lecture Data

Original Training Data

F1 values: 0, 0, 1, 1 → min=0, max=1

F2 values: 2, 5, 6, 8 → min=2, max=8

Normalizing F2: F2=5: (5−2)/(8−2) = 3/6 = 0.5 F2=8: (8−2)/(8−2) = 6/6 = 1.0 F2=6: (6−2)/(8−2) = 4/6 = 0.667 F2=2: (2−2)/(8−2) = 0/6 = 0.0 Test points F2: F2=3: (3−2)/(8−2) = 1/6 ≈ 0.167 F2=4: (4−2)/(8−2) = 2/6 ≈ 0.334

Accuracy is 98.2% — looks great! But recall is only 30%, meaning the classifier misses 70% of all positive cases. In a medical diagnosis scenario, this would be catastrophic. This is why we need precision, recall, and F1.

Interview Questions & Answers

Q1: Why is KNN called a lazy learner?
KNN does not build a model during training — it just stores all training data. All computation is deferred to prediction time. Training complexity is O(1). It's "lazy" because it waits until a query arrives to do any work, unlike "eager" learners like Decision Trees that build a model upfront.
Q2: What happens when K=1 vs K=N?
K=1: Very sensitive to noise — a single mislabeled point can cause wrong predictions. High variance, low bias. K=N (all data): Every test point gets the majority class of the entire dataset — essentially no learning. High bias, low variance. Best K balances these extremes.
Q3: Why use cosine similarity over Euclidean for text?
Euclidean distance is sensitive to document length — a longer document appears "farther" even if it has the same word distribution as a shorter one. Cosine similarity measures the angle between vectors, ignoring magnitude. Two documents with identical word proportions get cosine=1.0 regardless of length. This makes cosine ideal for text, where we care about topic/content, not document size.
Q4: What is the time complexity of KNN?
Training: O(1) — just store the data. Prediction (per query): O(N·d) where N=number of training points, d=dimensions. Space complexity: O(N·d). For large datasets, this makes KNN slow at prediction time. Solutions include KD-trees or Ball-trees to speed up neighbor search.
Q5: What is the Curse of Dimensionality and how does it affect KNN?
As dimensions increase, distances between all points become similar — there's no longer a meaningful "nearest" neighbor. Data becomes increasingly sparse. KNN accuracy degrades severely in high-dimensional spaces. Solution: Use dimensionality reduction (PCA), or switch to cosine similarity which depends on direction rather than magnitude.
Q6: How do you choose the optimal K?
1) Cross-validation: Try K=1,3,5,7... and pick the one with lowest validation error. 2) Use odd K for binary classification to avoid ties. 3) Heuristic: K ≈ √N. The optimal K is found at the bottom of the U-shaped error curve (bias-variance tradeoff).
Q7: What is the difference between precision and recall?
Precision = "Of all predicted positives, how many were actually positive?" (TP/(TP+FP)). Recall = "Of all actual positives, how many did we correctly identify?" (TP/(TP+FN)). A spam filter should have high precision (don't block legitimate emails). A cancer test should have high recall (don't miss cancer cases). F1 is the harmonic mean of both.
Q8: What is Bayes Error and why does it matter?
Bayes error is the theoretical minimum error any classifier can achieve given the underlying data distribution — it's the irreducible error caused by overlapping classes. If KNN achieves error ≈ Bayes error at some K, that K is near-optimal. In the lecture example, K=2 achieves error=0.17 ≈ Bayes error of 0.17, confirming K=2 is optimal.
Q9: What is feature scaling and why is it important for KNN?
KNN uses distances, so features with larger numeric ranges dominate the calculation. Without scaling, income ($10K–$1M) would completely overpower height (1.5m–1.8m). Min-max normalization scales all features to [0,1]: x_norm = (x−min)/(max−min). Always normalize before applying KNN!
Q10: When would you use Manhattan over Euclidean distance?
Manhattan is preferred when: (1) Data is high-dimensional (distances become more meaningful), (2) You need robustness to outliers (no squaring, so large differences don't dominate), (3) Movement is restricted to grid-like paths (like city navigation), (4) Features have different units and you want equal contribution from each dimension.
