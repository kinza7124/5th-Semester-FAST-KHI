Section 01

Introduction to Interface Design

💡

Core Idea: Initially users had to adapt to complex technical systems. Modern design flips this — technology must now adapt to human ease. Usability is the central concern.

Historical Context

  • Early interfaces were purely technical — users were expected to learn them.
  • A set of Golden Rules was defined to guide designers.
  • The concept of the "window world" (GUI) was introduced to make systems visual and intuitive.
  • Issues observed in bad GUI designs: Not user-friendly Confusing Counter-intuitive Frustrating
🌍 Real-World Example
  • Good UI: Apple iOS — icons, gestures, no commands needed.
  • Bad UI: Old command-line systems requiring memorised syntax (e.g., early UNIX for casual users).
  • Evolution: MS-DOS → Windows GUI → Touch interfaces → Voice UI (Alexa, Siri).

Section 02

Golden Rules of UI Design — Theo Mandel

🎓

Theo Mandel defined three fundamental principles that guide every aspect of UI design. These are extremely exam-important.

01

Allow Users to Maintain Control

Users must feel in charge — free to do what they want, switch modes, undo mistakes, and interact flexibly.

02

Reduce User's Memory Load

The system should remember things for the user. Use visuals, defaults, and shortcuts to minimise recall demand.

03

Make Consistent Interface

Patterns, colours, and interactions should remain predictable across all screens and applications.

Principle 1: Allow Users to Maintain Control — Details

1a. Define Interactive Modes Freely

Allow users to define different modes and switch between them easily at any time.

💻 Software Examples
  • MS Word: Switch between Editing Mode and Spell-Check Mode freely.
  • Chrome Browser: Normal mode vs. Incognito mode vs. Reading mode.
  • Adobe Photoshop: Selection mode, brush mode, crop mode — easy switching.

1b. Allow Flexible Interaction

Users should be able to interact via multiple input methods:

Mouse Keyboard Digitizer Pen Voice Input Multi-touch
💻 Software Examples
  • Windows OS: Mouse clicks, keyboard shortcuts, stylus on Surface devices, Cortana voice commands.
  • Google Docs: Keyboard, mouse, Google Assistant voice dictation, mobile touch.

1c. Allow Uninterruptable & Undoable Interaction

  • User can freely quit a task and do another without losing changes.
  • Undo/Redo must always be available.
💻 Software Examples
  • MS Word / Google Docs: Auto-save + unlimited Ctrl+Z undo.
  • Photoshop: History panel with 50+ undo steps.
  • Gmail: "Undo Send" feature — cancel a sent email within seconds.

1d. Allow Customized Operations (Macros)

Advanced users can create macros for frequently occurring operations to speed up workflow.

💻 Software Examples
  • MS Excel/Word: Record and run macros via VBA (Visual Basic for Applications).
  • AutoHotKey: Desktop macro scripting tool.
  • Photoshop Actions: Record repetitive tasks as a single-click action.

1e. Hide Technical Internals from Casual Users

Users should not need to know about the underlying OS, file systems, or backend complexities.

💻 Software Examples
  • iOS/Android: Users never see the file system or OS commands — apps handle everything.
  • MS Word: User clicks "Save" — no need to know about disk sectors, buffers, or OS file APIs.

1f. Design for Direct Interaction

Icons and objects should be draggable, scalable, and feel as if they physically exist.

💻 Software Examples
  • File Explorer: Drag files to folders — like moving physical folders.
  • Canva / Figma: Drag-and-drop UI elements, resize handles, direct manipulation.
  • Google Maps: Drag the map, pinch-to-zoom — direct interaction.
Principle 2: Reduce User's Memory Load — Details

2a. Well-Designed Systems Don't Test Memory

Use list boxes, checkboxes, dropdowns rather than empty text fields wherever possible. Display past inputs visually.

💻 Software Examples
  • Google Search: Auto-complete suggestions — no need to recall full queries.
  • Form dropdowns: Country picker uses a dropdown list, not a blank text box.
  • Spotify: Recently played shows your history — no memorisation needed.

2b. Establish Meaningful Defaults

Provide sensible default settings. Users can customise but always have a "Reset to Defaults" option available.

💻 Software Examples
  • Microsoft Word: Default font (Calibri 11pt), margins (1 inch) — sensible starting point.
  • Chrome: Default search engine set to Google; users can change it.
  • VS Code: Default dark theme + reset settings option.

2c. Define Intuitive Shortcuts

Shortcuts should be mnemonically obvious so users can guess or remember them easily.

ShortcutActionSoftware
Ctrl+PPrintAll Windows apps
Ctrl+SSaveMS Office, VS Code
Ctrl+ZUndoUniversal
Ctrl+C / VCopy / PasteUniversal
Ctrl+FFindBrowser, Word, Notepad

2d. Visual Layout Near Real-World Processes

The steps in software should mirror real-life procedures — don't re-invent familiar sequences.

💻 Software Examples
  • Online Bill Payment: Select bill → Enter amount → Confirm → Receipt. Same as real-world bank payment.
  • E-Commerce Checkout (Amazon): Cart → Address → Payment → Review → Place Order. Mirrors physical store checkout.

2e. Disclose Information Progressively

Show only what's needed. Reveal more detail on demand (clicks, hover, expand). Avoid overwhelming the user upfront.

💻 Software Examples
  • Amazon Product Page: Shows image + price first → click for full specs, reviews, Q&A sections.
  • Accordion menus in mobile apps: Tap a category to expand sub-items.
  • Gmail: Shows subject line in list → click to see full email body.
Principle 3: Make Consistent Interface — Details

3a. Meaningful Context for Tasks

Users should always understand where they are and what they are doing — use window titles, breadcrumbs, colour coding.

💻 Software Examples
  • MS Word: Title bar shows filename + "Word" — user knows what app and file they're in.
  • E-commerce sites: Breadcrumb trail: Home > Electronics > Phones > iPhone 15.
  • Jira: Colour-coded tickets by status — red = blocked, green = done.

3b. Consistency Across Application Family

A suite of applications should share the same visual language — menus, fonts, colours, and patterns.

💻 Software Examples
  • Microsoft Office Suite: Word, Excel, PowerPoint, Outlook all share the Ribbon interface, font chooser, colour picker.
  • Google Workspace: Docs, Sheets, Slides share the same top-bar, share button, file-menu structure.
  • Adobe Creative Cloud: Photoshop, Illustrator, InDesign share Layers panel, tools panel layout.

3c. Don't Redefine User's Past Experiences

Never reassign globally known shortcuts or interaction patterns unless absolutely forced to.

⚠️

Classic Bad Example: If a new app binds Ctrl+S to Scale instead of Save, users will lose work constantly because muscle memory expects Save. This violates consistency.

💻 Good Examples of Consistency
  • All browsers use Ctrl+T for new tab, Ctrl+W to close.
  • File → Save, Edit → Undo, View → Zoom are universal menu positions.

Three Models Explained

Step 1: Interface Analysis

User Analysis

  • Understand the users of the system, system goals, displayed content, and environment.
  • The mental image and implementation model must converge — achieved by understanding how users use the system.

Information Sources for System Understanding

SourceMethod
User InterviewsDevelopment team meets end-users to identify needs and work culture.
Marketing & Sales InputMarket surveys to find how many ways the product could be useful.
Support InputSupport staff collects feedback on what works/doesn't, what's easy or difficult.

User Analysis — Key Questions (Exam Important!)

These questions help in better user categorisation:

  • Are users trained professionals, technicians, clerical, or manufacturing workers?
  • What is the average formal education level of users?
  • Do users prefer written materials or classroom training?
  • Are users expert typists or keyboard-phobic?
  • What is the age range and gender of the user community?
  • How are users compensated? What are their working hours?
  • How frequently will they use the software? (mostly / occasionally)
  • What is the primary spoken language of users?
  • What are the consequences of a user's mistake in the system?
  • Are users subject-matter experts? Are they interested in the underlying technology?
Task Analysis & Modelling

Workflow & Swim Lane Diagram

A Swim Lane Diagram is a type of flowchart that shows process steps and assigns responsibility to different roles (lanes).

📊 Example — Order Processing Swim Lane

Lanes: Customer | Sales Rep | Warehouse | Finance

Customer places order → Sales Rep confirms → Warehouse ships → Finance invoices. Each step sits in the responsible party's lane.

Analysis of Display Content & Environment

Two More Analysis Dimensions

  • Display Content Analysis: Format, aesthetics, and progressive disclosure of content. What to show, how to show it, and in what sequence.
  • Physical Work Environment Analysis: Workplace must allow proper operation and concentration. Software aesthetics must co-relate with the physical setting (e.g., dark mode for dim rooms, high-contrast for bright environments).
💻 Examples
  • Display Content: E-commerce shows product image first → click for full specs (progressive disclosure).
  • Environment: Air Traffic Control UI — high contrast, no distracting animations, large readable fonts due to high-stakes physical environment.
Step 2: Interface Design

UI Design Steps (from Design Models)

  1. Define interface objects (buttons, text fields, video, icons) and operations (tasks).
  2. Define events (user actions) that change the UI state.
  3. Depict each interface state as it will look to the end-user — use sketches/wireframes.
  4. Show how the user can infer the system state from the information provided through the interface.

Applying Design Steps — Object Classification

  • Create a list of objects and actions → categorise them into types:
    • Source Objects: E.g., Printer icon (originates an action).
    • Target Objects: E.g., Paper (receives the action).
    • Application Objects: E.g., Screen, database table/entity.
  • Use UI Design Patterns — pre-formulated solutions for well-bounded problems.
    📅 Example — Calendar Strip Pattern

    A Calendar Strip shows dates in a horizontal row, highlights today, allows forward/backward navigation — a reusable UI pattern.

Section 05

Interface Design Issues (6 Issues)

📋

Six key design issues must be addressed in every interactive system. These are very likely to appear in exams.

Issue 1: System Response Time ⏱️

Primary complaint for almost every interactive system. Has two critical characteristics:

CharacteristicProblem if ViolatedExample
LengthLonger response times → user frustration; users abandon tasks.Page takes 10s to load → user leaves.
VariabilityVarying response times → user confusion — they wonder if something went wrong at the backend.Usually loads in 1s, suddenly takes 7s — user unsure if it's broken.
💻 Software Solutions
  • Progress bars / spinners (Gmail, Chrome) — inform the user that work is ongoing.
  • Skeleton screens (Facebook, LinkedIn) — show placeholder shapes while content loads.
  • Optimistic UI updates (Twitter/X likes) — update UI instantly, sync with server in background.

Issue 2: Help Facilities ❓

Every system must provide help mechanisms. Design questions to address:

  • Is help available for all functionalities?
  • How will the user demand help? (Menu option? Function key like F1?)
  • How is help presented? (Separate window? Tooltip? Printed manual?)
  • How does the user return to normal UI after consulting help?
💻 Software Examples
  • MS Office: F1 opens full Help documentation in a panel — context-sensitive help.
  • Windows: ? icon in dialog boxes → tooltip explanation.
  • Slack / Intercom: In-app chat-based help widget (bottom right corner).
  • Figma: Tooltips on every tool explaining the shortcut and function.

Issue 3: Error Handling 🚨

Error messages are bad news — they must be designed to minimise user frustration and guide recovery.

✅

A good error message must:

  • Describe the problem simply — plain language, no jargon.
  • Provide valuable advice — tell the user what to do next (use hyperlinks).
  • List negative consequences of the error (what data may be lost, etc.).
  • Visual prompting — use colour scheme (red border, warning icon) to categorise it clearly as an error.
💻 Software Examples
  • Gmail — "Message too large": Explains size limit, links to how to share via Google Drive instead.
  • Chrome Error 404: Clear message, suggests going back or checking URL. Friendly dinosaur reduces frustration.
  • Form validation (React/HTML5): Red border + helper text below field ("Email must contain @").

Issue 4: Menu & Command Labelling 📋

  • Different styles: Command-oriented architecture vs UI-based architecture — both used frequently.
  • Commands assigned to menu items should also be executable without the UI (via keyboard/CLI).
💻 Software Examples
  • MS Word: Menu shows "File → Save" and also shows shortcut Ctrl+S — both work.
  • VS Code: Every action in menu has a command palette equivalent (Ctrl+Shift+P).
  • Linux: GUI file manager actions also available via terminal commands.

Issue 5: Application Accessibility ♿

UI must cater to the needs of physically challenged persons.

💻 Software Examples
  • Windows Narrator: Screen reader for visually impaired users.
  • iOS VoiceOver / Android TalkBack: Full screen reader on mobile.
  • Dragon Naturally Speaking: Voice input for users with motor disabilities.
  • Web WCAG Standards: Alt text for images, keyboard-only navigation, sufficient colour contrast ratio.
  • YouTube: Auto-generated captions for hearing-impaired users.

Issue 6: Internationalization 🌐

UI must target the global market — follow global design standards and support multiple languages.

💻 Software Examples
  • Google Chrome: Automatically detects page language and offers translation.
  • MS Office: Available in 100+ languages with localised menus, date formats, currency symbols.
  • WhatsApp: Supports RTL (right-to-left) layout for Arabic/Hebrew users.
  • iOS/Android: System-wide language switching affects all apps.

Section 06

Revised Interface Design Guidelines

Key Guideline Insights

  • In interactive systems, completing tasks quickly matters — relevant options must be easily accessible and in a larger size.
  • Important buttons should be made bigger to reduce accessibility time (Fitts's Law: bigger target = faster to click).
  • Inter-related targets should be placed together to reduce movement time between clicks.
💻 YouTube Example
  • Volume/sound controls are placed at the bottom, near the video (related controls grouped).
  • The Subscribe button is bigger than other buttons to increase clicks.
  • Play/Pause is the largest button — most frequently used, follows Fitts's Law.

Section 08

Exam Questions & Answers

💡

Tap any question to reveal the model answer. All answers are detailed and exam-ready.

Q1
What are Theo Mandel's three golden rules of UI design? Explain each with examples.
▼

Theo Mandel defined three fundamental principles:

  • 1. Allow Users to Maintain Control: Users must freely choose modes, interact via multiple inputs (mouse, keyboard, voice), undo/redo actions, create macros, and interact directly with on-screen objects. Example: MS Word's spell-check/editing mode switch; Photoshop's undo history.
  • 2. Reduce User's Memory Load: Use list boxes/dropdowns instead of blank text inputs. Save past inputs. Establish defaults. Bind intuitive shortcuts (Ctrl+P = Print). Mirror real-world processes. Use progressive disclosure. Example: Amazon auto-complete, Gmail's draft saving.
  • 3. Make a Consistent Interface: Use consistent labelling, colour coding, and layout across all app screens and across a product suite. Don't re-assign known shortcuts. Example: MS Office Ribbon, consistent Ctrl+S = Save everywhere.
Q2
Explain the UI Design Models. What is the goal of an effective UI design in terms of models?
▼

There are three models in UI design:

  • Design Model: Created by the software engineer/designer — how they intend the system to work based on requirements.
  • User's Mental Model: The internal picture the user forms about how the system works, based on their interaction and past experience.
  • System Image: The actual interface the user sees — the intersection of the design model and user experience.

Goal: An effective design is one in which the user's mental model and the implementation (design) model coincide — the user's understanding perfectly matches how the system actually works. This is achieved through good interface analysis, consistent design, and user testing.

Q3
What is the UI Analysis and Design Process? Why is it called iterative?
▼

The UI Analysis and Design Process follows the Spiral Process Model and consists of 4 steps:

  1. Interface Analysis: Understand users, tasks, environment, and display content.
  2. Interface Design: Define objects, operations, events, and sketch interface states.
  3. Interface Implementation/Construction: Build prototypes and working UI using a prototyping approach.
  4. Interface Validation: Test the interface against user needs and refine.

Why Iterative? It uses the spiral model — these 4 steps are repeated (iterated) again and again. Each cycle produces a more refined and improved design. No single pass is sufficient for a quality UI.

Q4
What are the six design issues in interface design? Explain system response time in detail.
▼

The six design issues are: (1) System Response Time, (2) Help Facilities, (3) Error Handling, (4) Menu & Command Labelling, (5) Application Accessibility, (6) Internationalization.

System Response Time in detail:

  • It is the primary complaint for almost every interactive system.
  • Length: Longer response times lead to user frustration — users may abandon the task entirely. Every second of delay reduces satisfaction.
  • Variability: Inconsistent response times cause confusion — users wonder if the system malfunctioned. A system that sometimes takes 1s and sometimes takes 8s is worse than one consistently taking 3s.
  • Solution: Use progress bars, skeleton screens, spinners, and optimistic UI updates to manage user perception during wait times.
Q5
What is Interface Analysis? List and explain the information gathering methods used.
▼

Interface Analysis is the first step in the UI design process. It involves understanding the problem before designing the solution — specifically understanding users, system goals, content, and the environment.

The mental image (user's model) and the implementation model must converge, which is only possible by deeply understanding users and how they use the system.

Three information sources:

  • User Interviews: Development team meets directly with end-users to identify needs, workflows, and work culture.
  • Marketing & Sales Input: Market surveys to understand in how many ways the product could be useful to different segments.
  • Support Input: Support staff collects feedback on what features work or don't, what's easy or confusing — direct from real users.
Q6
What are the characteristics of a good error message? Give examples.
▼

A good error message must include:

  • Describe the problem simply: Use plain language, no technical jargon. Say what went wrong clearly.
  • Provide valuable advice: Tell the user what to do to fix it. Include hyperlinks to solutions.
  • List negative consequences: Tell the user what data might be lost or what can't be recovered.
  • Visual prompting: Use a colour scheme (red, orange) and icons (⚠️, ❌) that make it immediately clear this is an error — distinct from normal UI.

Bad error: "Error 0x80070570" — meaningless to a casual user.

Good error: "Your file couldn't be saved because the disk is full. Free up at least 500MB and try again. [Click here for help]" — descriptive, actionable, visually distinct.

Q7
Explain Task Analysis and its components in the context of interface analysis.
▼

Task Analysis is performed after User Analysis. It identifies and models the tasks users will perform to achieve system goals.

Components:

  • Task Identification: Identify all tasks and sub-tasks performed in specific circumstances.
  • Use-Cases: Define basic interactions between actor and system in informal paragraphs. Used to derive tasks, sub-tasks, and UI requirements.
  • Task Elaboration: Stepwise refinement — break down complex tasks into detailed sub-steps. Can be manual or derived from existing systems.
  • Object Elaboration: Extract physical objects (entities) from the system to define their classes and behaviours (links to OOP concepts).
  • Workflow Analysis: Define how work processes are completed across multiple people and roles — represented using UML Swim Lane Diagrams.

Q9
What is progressive disclosure in UI design? Give examples.
▼

Progressive Disclosure is a UI design technique where information is displayed gradually — only what is needed at the current step is shown, with more detail revealed on demand.

Why it matters: It reduces cognitive overload, making complex systems appear simple to new users while keeping full functionality accessible to advanced users.

Examples:

  • E-commerce (Amazon): Product listing shows image + price → click for full description, specs, customer reviews.
  • Gmail: Inbox shows sender + subject → click to see full email body, headers, attachments.
  • Accordion menus (mobile): Top-level categories visible → tap to expand sub-items.
  • Advanced settings: Basic settings shown by default → click "Advanced" to reveal more options (e.g., Chrome settings).

Q11
What are the user analysis questions for better user categorisation? Why are they important?
▼

These questions help designers understand WHO they are building for, ensuring the UI is appropriate for the actual user population:

  • Are users trained professionals, technicians, clerical, or manufacturing workers?
  • Level of formal education of an average user?
  • Do users prefer written materials or classroom training?
  • Are users expert typists or keyboard-phobic?
  • Age range and gender of user community?
  • Working hours — normal office hours or until the job is done?
  • How frequently do they use the software? (mostly/occasionally)
  • Primary spoken language among users?
  • Consequences of a user's mistake in the system?
  • Are users subject matter experts? Are they interested in the underlying technology?

Importance: Answers determine the UI complexity level, training support needed, language/localisation requirements, error tolerance design, and accessible design considerations.

Q12
What is internationalization in UI design? Why is it important and how is it implemented?
▼

Internationalization (i18n) is the process of designing a UI that can be adapted to different languages, regions, and cultures without requiring engineering changes to the core codebase.

Why important: Modern software targets a global market. A product that only works in English excludes billions of potential users. Legal requirements in some regions also mandate language support.

Implementation:

  • Support multiple languages — all text stored in separate language files (not hardcoded).
  • Support RTL (right-to-left) layouts for Arabic, Hebrew, Urdu.
  • Localise date/time formats (MM/DD/YYYY vs DD/MM/YYYY), currency symbols, number formats.
  • Use Unicode for character encoding to support all scripts.
  • Follow global design standards (ISO, WCAG).

Examples: WhatsApp (RTL support), MS Office (100+ languages), iOS/Android (system-wide language switching).

Q13
What is the difference between a wireframe, storyboard, and prototype?
▼
  • Wireframe: A low-fidelity structural sketch of the UI layout — shows element placement without visual design (no colours, no images). Like an architectural blueprint. Tools: Balsamiq, Figma (draft mode).
  • Storyboard: A sequence of screen images that show the user's journey through the interface — scene by scene, like a comic strip. Shows the flow and context of interactions.
  • Prototype: A higher-fidelity, interactive model of the UI — may be clickable/tappable. Used for user testing before development. Tools: Figma, Adobe XD, InVision, HTML/CSS mock.
Q14
What is a Swim Lane Diagram and where is it used in UI design?
▼

A Swim Lane Diagram is a type of UML process flowchart that visually divides responsibilities across multiple actors or departments (each "lane" represents one actor/role).

Use in UI design: It is used in Workflow Analysis during Interface Analysis to show how a complete work process is accomplished when multiple people and roles are involved. It clarifies who does what, in what sequence, and how handoffs occur between roles.

Example: An online order process swim lane might have: Customer | Sales System | Warehouse | Accounts. Each step (place order, confirm, pack, invoice) appears in the correct actor's lane with arrows showing flow between lanes.

Q15
What is accessibility in UI design? Why must UI cater to physically challenged users?
▼

Accessibility in UI design means ensuring that software can be used effectively by people with disabilities — visual impairments, hearing impairments, motor disabilities, or cognitive challenges.

Why it matters:

  • Ethical responsibility: Everyone has the right to use technology.
  • Legal compliance: Many countries mandate accessibility (ADA in USA, EN 301 549 in EU).
  • Market reach: Over 1 billion people worldwide have a disability — a huge user segment.
  • Better design for all: Accessible design often benefits all users (e.g., captions help people in noisy environments, not just the hearing-impaired).

Examples of accessible features: Screen readers (iOS VoiceOver), voice input (Dragon Naturally Speaking), keyboard-only navigation, sufficient colour contrast (WCAG AA: 4.5:1 ratio), alt text for images, captions for videos.
